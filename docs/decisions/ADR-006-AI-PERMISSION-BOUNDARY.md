# ADR-006: Backend Tool Enforcement & Zero-Credential AI Boundary

## Context
Generative AI models are vulnerable to prompt injections, hallucinations, and non-deterministic logic. Allowing an LLM to hold database passwords, cloud tokens, or unrestricted SSH shell access introduces catastrophic security vulnerabilities into customer environments.

## Decision
Enforce a strict architectural boundary between the AI Model and external systems:
1. **The AI receives ZERO raw credentials**: Abstract resource IDs are used exclusively in prompts and tool arguments.
2. **Mandatory Backend Tool Mediation**: Every tool invocation generated by the AI is intercepted, validated, and evaluated against the project's permission policy and user role.
3. **Tier-Based Approval Gate**: Any destructive or production-altering action (e.g. branch push, service restart, server reboot) halts execution until explicit customer confirmation is received.

## Consequences
- **Positive**: Eliminates credential leakage via prompt injection; ensures non-repudiation; guarantees human oversight over production infrastructure.
- **Negative**: Adds backend validation latency and requires asynchronous state management for user approvals.

## Alternatives Considered
- **Direct Agent Execution (Giving LLM shell/credential access)**: Rejected as an unacceptable security risk for production environments.
- **Purely Read-Only AI (No operational tools)**: Rejected because Ryvix's primary value is autonomous operations and code remediation.
