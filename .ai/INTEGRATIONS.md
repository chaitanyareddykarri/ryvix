# Ryvix Integration Interfaces & Contracts

This document summarizes the external integration contracts implemented across Ryvix.

---

## 1. GitHub Integration

- **Mechanism**: GitHub App (recommended) or OAuth App.
- **Permissions**: Read/Write access to Code, Pull Requests, Issues, and Commit Statuses for authorized repositories only.
- **Key Responsibilities**:
  - Fetch tree structure and file contents for Project Analyzer.
  - Clone repository into ephemeral coding workspaces using temporary installation tokens.
  - Create feature branches, commit diffs, and open Pull Requests.
  - Listen to webhook events (`push`, `pull_request`, `check_run`).
- **Security Constraint**: Tokens are short-lived, generated by backend service accounts, and never transmitted to the client or AI context.

---

## 2. Supabase Backend Foundation

- **Components Utilized**:
  - **Auth**: JWT session handling, social OAuth (GitHub), email magic links / OTP.
  - **PostgreSQL**: Relational database with multi-tenant Row Level Security (RLS).
  - **Realtime**: WebSocket subscriptions for task state transitions, Web Chat streaming, and live telemetry feeds.
  - **Storage**: S3-compatible buckets for ephemeral frontend preview bundles and build artifacts.
- **Boundary**: Edge functions handle light webhooks; long-running operations are dispatched to Ryvix Workers via Redis/Postgres queue.

---

## 3. Hugging Face AI Gateway

- **Role**: Primary intelligence layer for complex reasoning, planning, code modification, and incident forensics.
- **Deployment**: Dedicated Hugging Face Inference Endpoint or serverless Inference API.
- **Protocol**: OpenAI-compatible chat completions or native Hugging Face text-generation endpoints using streaming JSON tool-calling schemas.
- **Fine-Tuning Strategy**: Future fine-tuned Ryvix models trained exclusively on verified, sanitized, and anonymized task execution runs.

---

## 4. Communication Integrations

### WhatsApp
- **Provider**: Meta WhatsApp Cloud API or Twilio Business API.
- **Channel Purpose**: Urgent incident notifications, interactive approval prompts (interactive buttons), and mobile status queries.
- **Payload Handling**: Inbound webhooks validated via HMAC-SHA256 signature; user numbers mapped to verified Ryvix profile IDs.

### Gmail
- **Provider**: Google Workspace / Gmail API (OAuth 2.0).
- **Channel Purpose**: Asynchronous notifications, task summary digests, and customer command ingestion via email replies.
- **Strict Distinction**: Transactional authentication emails (login OTPs, password resets) use dedicated high-reputation SMTP providers (e.g., SendGrid/Postmark), NOT customer Gmail OAuth credentials.

---

## 5. User Server Connectors

### Internal Connector (Agent Daemon)
- **Deployment**: Lightweight binary (Go/Rust/Node) or Docker container running inside the customer environment.
- **Capabilities**:
  - Metrics: CPU, memory, disk I/O, network bandwidth, container runtime stats.
  - Logs: Tail systemd journal, Docker container logs, application file logs.
  - Controlled Actions: Whitelisted service restarts, health checks, log file truncation.
- **Protocol**: Outbound WebSocket / gRPC over TLS to Ryvix Ingestion Gateway (no inbound ports required on customer server).

### External Connector (Out-of-Band Control Path)
- **Deployment**: Standalone probe worker running within Ryvix infrastructure.
- **Capabilities**:
  - Synthetic Health Probing: Multi-region HTTP/HTTPS/TCP health checks.
  - Infrastructure Recovery: Invokes customer-authorized cloud provider APIs (AWS EC2, DigitalOcean, Hetzner, etc.) to reboot or restart frozen instances when the internal connector stops responding.
